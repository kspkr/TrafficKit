# Security model

TrafficKit sees everything that passes through it: passwords, session cookies,
API keys, personal data. It is also a program that accepts network
connections. Both facts drive the decisions below.

## What we protect against

1. **Other machines** reaching the proxy or the control API.
2. **Web pages** in a browser on the same machine talking to the control API
   (CSRF, DNS rebinding).
3. **Other local processes and users** reading captured traffic through the
   control API.
4. **Captured content** attacking the UI (script in an HTML response, huge
   bodies, decompression bombs, malformed encodings).
5. **Accidental disclosure** of captured data or keys through logs, crash
   reports, telemetry or exports.

We do not defend against malware already running as the same OS user; it can
read process memory and the user's files regardless.

## Decisions

**Loopback by default.** The proxy binds `127.0.0.1`. Binding any other
address requires `proxy.allowRemote: true` in config; the API refuses
otherwise with `remote_bind_disabled`. The control API only ever binds
`127.0.0.1`, with no option to change it.

**Per-launch API token.** 32 random bytes from `crypto/rand`, generated by the
engine on start and compared in constant time. It's handed to the desktop
shell over stdout, and written to `<dataDir>/engine.json` (mode 0600, and
under `%AppData%` on Windows) so `traffickit mcp` can find the engine. That
file sits next to the CA key and has the same audience: the current user.
It's removed when the engine exits.

**Host and Origin checks** on every API request (see [IPC](../architecture/ipc.md)).
Requests with a foreign `Host` get 421, foreign `Origin` get 403. CORS headers
are only ever sent for allow-listed origins.

**Input validation.** JSON bodies are size-limited and decoded strictly.
Ports, bind addresses and IDs are parsed and range-checked before use. The
engine never runs shell commands; nothing from the API reaches `exec`.

**Captured data is untrusted.** The UI renders captured content as text nodes
(React escapes), never via `innerHTML` or `dangerouslySetInnerHTML`. HTML
bodies are shown as source. When a sandboxed preview is added it will use an
`<iframe sandbox>` with no `allow-scripts` and a restrictive CSP. The body
endpoint always answers `application/octet-stream` with `nosniff` and a
sandbox CSP, so even a navigated URL cannot render captured markup. Decoding
is capped at 64 MiB of output.

**Logs don't carry secrets.** Structured logs record host, method, status and
error class. They never include header values, bodies, query strings or the
API token. Debug level adds the path, still without the query string.

**No outbound traffic of our own.** No telemetry, update checks or crash
uploads. If an optional feature ever needs the network (e.g. update checks),
it will be off by default and listed in this document.

**Proxy loop protection.** Requests addressed to the proxy's own port are
rejected with 508 instead of recursing. The one exception is the reserved
name `traffickit.test`, which the proxy answers itself with a static page
(no scripts, `default-src 'none'` CSP).

## HTTPS interception

Interception needs a local certificate authority whose key can mint a
certificate for any site. That key is the most sensitive thing TrafficKit
owns.

- **Where it lives.** `<dataDir>/ca/ca.key`, PKCS#8 ECDSA P-256, written with
  mode 0600 (on Windows, `%AppData%` is already private to the user). It
  never leaves that folder, is never served by any endpoint, and is never
  included in exports. `GET /v1/https/ca.pem` and the proxy's `/certificate`
  page serve only the public certificate.
- **Identity.** The subject names the machine and creation date
  (`TrafficKit Local CA (host, 2026-09-28)`), so it's obvious in a trust
  store which one it is. It's valid for a year and is replaced automatically
  within a week of expiry. Settings → HTTPS can regenerate it at any time;
  launched browsers are closed when that happens because they trust the old
  key.
- **Never installed system-wide.** Launched browsers trust it through
  Chromium's `--ignore-certificate-errors-spki-list`, which is pinned to this
  CA's public key and applies only to that browser instance and its
  throwaway profile. Launched terminals trust it through per-process
  environment variables. Your normal browser and the OS trust store are
  never touched. Trusting it anywhere else is a manual step the user takes,
  with the file and fingerprint shown in the app.
- **Leaf certificates** are issued per host on demand (30 days, cached in
  memory, never written to disk).
- **Upstream TLS is verified normally.** Interception terminates the
  client's TLS only; the connection to the real server is a separate TLS
  session verified against the system roots, so a MITM between TrafficKit
  and the server is still detected and reported.
- **Pinning is respected.** An app that rejects our certificate shows up as
  a `tls_untrusted` exchange with an explanation. Hosts can be exempted with
  the passthrough list. No bypass tooling is shipped.

## Launching browsers and terminals

The engine starts processes only from a fixed list of detected executables
(well-known install paths, never a path from the API). The only
client-controlled argument is the start URL, which must parse as an absolute
`http` or `https` URL, so it can't smuggle in a command-line flag or a
`file:`/`javascript:` URL. Launched processes are killed when the engine
exits and their temporary profiles deleted.

## AI assistants (MCP)

`traffickit mcp` is a client of the same control API, with the same token.
It adds nothing the UI can't do, but its output leaves the machine: it goes
to whichever AI provider the assistant uses. So:

- **Redaction on by default.** Credential headers, cookie values,
  secret-looking query parameters, form fields and JSON fields (including
  JSON nested in strings), JWTs and bearer tokens are replaced before a
  result is returned, and the result lists what was hidden. `--no-redact` is
  an explicit opt-out on the command line the user registers.
- **Bounded output.** Binary bodies are never returned; text bodies are cut
  to 8 000 characters by default (100 000 max).
- **Visible.** The MCP server identifies itself with `X-TK-Client`; the app
  shows "AI connected: <name>" while an assistant is using it and lists
  recent assistants in Settings.
- **Prompt injection.** Captured content is attacker-controlled. The server
  instructions tell the assistant to treat it as data. Tools that act are
  limited to launching an isolated browser, closing windows TrafficKit
  opened, and clearing captures; none can run commands or read files.
